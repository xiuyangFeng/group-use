# 跨平台文件夹加密软件 · 技术调研备忘

**时间** 2026-11 ｜ 2–5 人科研组，三平台，防同实验室同事与共享盘泄露，涉患者隐私/伦理审查 ｜ 只做选型，不含代码。

## 0. 结论先行

1. 三种形态相当于三个产品：**应用内预览/导出**最稳，适合 MVP；**原地解密**只当临时工作区；**虚拟磁盘**体验最好但要驱动，放后期。
2. 不要自创加密格式：用 **per-file 加密目录**（思路同 Cryptomator / gocryptfs），Argon2id 派生 KEK、随机 vault key、XChaCha20-Poly1305 分块；**文件名必须加密**。
3. 多人共用：**每人一把 X25519 公钥包裹同一个 vault key**，不要共享口令。
4. macOS 原生右键 = Finder Sync，对外分发需 Developer ID + 公证（$99/年）；MVP 不做，用菜单栏 + 拖拽 + 服务。Windows HKCU 右键无需管理员；Linux 用脚本/服务菜单。
5. 推荐：**Python 3.12 + PySide6 + PyInstaller + PyNaCl + pystray**，先 per-file vault + 应用内访问，二期评估 WinFsp / macFUSE 挂载。

## 1. 三种解锁形态

| 形态 | 明文落盘 | macOS | Linux | Windows | 主要代价 |
|---|---|---|---|---|---|
| a 原地解密 | 是（整段） | 可，无驱动 | 可 | 可 | 崩溃/备份/同步残留；共享盘传明文；双倍空间 |
| b 应用内预览/导出 | 预览否，导出是 | 可 | 可 | 可 | 只能用自家 app；导出即出保护边界 |
| c 虚拟磁盘 | 否（内核呈现） | macFUSE / FUSE-T | FUSE3 免 root | WinFsp / Dokan 驱动 | 驱动签名、MDM、稳定性 |

**(a) 原地解密**：实现最直接，但解锁窗口内任何进程和同事都能读；崩溃、备份/同步、APFS 快照都可能留明文；在共享盘上原地解密还会把明文经 SMB 传输。只应作为显式临时工作区：倒计时回加密、退出清理；不要承诺"安全擦除"（SSD 不可靠）。

**(b) 应用内预览/导出**：不装驱动、不要管理员、三平台一致，最适合 MVP。预览在内存解码；导出必然落盘，需用户选目标并清理临时文件。要关闭 QuickLook/缩略图/剪贴板/拖拽等旁路。DICOM 可流式解码，超大序列需限流。

**(c) 虚拟磁盘**：体验最接近普通文件夹（VeraCrypt 同路线），代价在系统层：

| 平台 | 方案 | 管理员 | 签名/公证 | 主要坑 |
|---|---|---|---|---|
| macOS | macFUSE 5（kext/FSKit）、FUSE-T | kext 需管理员 + 恢复模式降安全；FSKit 未核实 | kext 需签名/公证 | MDM 常禁第三方 kext；装完重启 |
| Windows | WinFsp 2.1、Dokan 2.x | 装驱动需管理员 | 驱动已签，exe 仍需签 | 无管理员基本无解 |
| Linux | FUSE3 + fusermount3 | 装包需 root，挂载不用 | 不需要 | 容器/WSL 缺 /dev/fuse；swap 未加密 |

- macFUSE 5.0（2025-05）起支持 FSKit；传统 kext 在 Apple silicon 上要求降低安全性并允许第三方内核扩展[1][2][3]。FUSE-T 走用户态 NFSv4、免 kext，但安装是否需管理员未核实[4]。FSKit 需 macOS 15.4+，成熟度未核实[5]。
- WinFsp 2.1（2025）驱动已签名，rclone/Cryptomator 在用，优先选它；但安装要管理员，无管理员只能退回应用内访问[6][7][28]；Dokan 同样[8]。
- Linux 由 setuid 的 fusermount3 代普通用户挂载，装包才要 root[9]。
- 安全策略：macOS MDM 可禁 kext；Windows WDAC/AppLocker 可拦未签名 exe/驱动；Linux 有 noexec、容器、SELinux 限制。拦截率未核实。
- 结论：虚拟盘不是 MVP；若做，Linux 先跑通，Windows 需一次管理员，macOS 最后。

## 2. 加密实现

| 方案 | 优点 | 局限 | 适用 |
|---|---|---|---|
| age | 简单、抗误用、X25519+ChaCha20-Poly1305、多收件人 | 整文件流式、无随机读、无文件名加密、无撤销 | 导出/备份/单文件 |
| libsodium secretstream | XChaCha20-Poly1305 分块、可随机读、配 Argon2id | 容器格式要自己设计 | 自建 vault（推荐） |
| AES-256-GCM + Argon2id | AES-NI 快、库多 | nonce 管理易错，随机 nonce 有碰撞上限 | 有密码学经验时 |
| Cryptomator v8 / gocryptfs | 文件名 AES-SIV、目录随机 ID、经审计 | 绑定 FUSE 或 Java | 复用其设计 |

- **目录树与文件名**：必须加密，否则"患者姓名/CT/日期"直接泄漏。文件名用确定性 AEAD（AES-SIV）以支持按名查找；目录名用随机 ID，重命名只改父目录映射。会泄漏文件数/层级/近似大小；密文名变长，注意 Windows 260 上限。
- **大文件**：1 MiB 分块 AEAD，nonce = 文件 ID + 块号，AAD 绑定文件 ID/块号防重排，末块标记防截断；支持随机读与断点续传。
- **大量小文件**：每文件 header + open/fsync 是瓶颈；几千个 0.5 MB DICOM 建议打包小文件（<64 KB 合并）或批量提交，先实测。
- **断点续传**：写 `.part`，逐块 fsync，完成后原子 rename；密文头存版本/长度/块大小。
- **增量**：per-file 天然增量，只重加密改动文件；单容器要块级 dirty bitmap，复杂，不建议 MVP。
- **不要用**：ZIP 传统加密（可破）、7z 整包（每次全量重写）、自创 KDF/模式。见 [24][25][26][27]。

## 3. 多用户密钥管理

| 方案 | 加人 | 改口令/离组 | 追责 | 实现量 | 结论 |
|---|---|---|---|---|---|
| 共享口令 | 给口令 | 改口令只重包 vault key；离组要换 key + 全量重加密 | 无 | 1 天 | 不推荐 |
| age 多收件人 | 加公钥 | 删 stanza（重写 key 文件），数据不动；已复制的 key 收不回 | 弱 | 2–3 天 | 可用 |
| OpenPGP | 导入公钥 | 同上 | 中 | 1 周 | 不推荐（UX 差） |
| X25519 包裹 + owner 签名 header | 加 sealed box | 删 stanza + 轮换 vault key（需重加密） | 强，可加审计 | 1–2 周 | **推荐** |

- 结构：随机 vault key（32 B）加密数据；每人一对 X25519，私钥经 Argon2id 包裹；vault key 用 `crypto_box_seal` 分别封给成员公钥、写入 header；owner 用 Ed25519 签名 header 防篡改。
- 关键事实：**删成员只能阻止其未来解密，收不回已复制的 vault key**；真吊销必须换 vault key 并重加密全部数据。其价值在追责与不共享口令，不是强吊销。
- 2–5 人：per-user 密钥 + owner 签名 + append-only 审计日志（谁、何时、解锁/导出）有助于满足伦理审查的访问控制/日志要求；离组回收、销毁记录、密钥托管/恢复流程要事先定（PI 离职、学生毕业）。
- 并发：共享盘上多人同时写同一 vault 会冲突，Cryptomator 也提示"文件正在使用"[10]；建议锁文件/租约 + 单写者，或按子目录分片。

## 4. GUI / 托盘 / 右键菜单

| 方案 | 体积（经验值） | 托盘 | 右键（三平台） | 上手 | 结论 |
|---|---|---|---|---|---|
| Python + PySide6 + PyInstaller | 150–250 MB | pystray，Linux 需 AppIndicator | Win HKCU ✓；Linux 脚本 ✓；macOS ✗ 需 Swift appex | 最快 | MVP 推荐 |
| Tauri v2 | 10–20 MB | 内置 tray | 同上；macOS 仍需 appex | 中（Rust） | 二期/长期 |
| Electron | 120–200 MB | Tray | 同上 | 快（JS） | 不推荐（体积/内存） |
| Rust 原生 | 5–15 MB | tray-icon | 同上 | 慢 | 不适合小团队 |

- **macOS Finder Sync**：Finder 右键扩展是 `.appex`，必须嵌在已签名 app 内；对外分发要 Developer ID + 公证，即 Apple Developer Program（$99/年）[11][12]。免费 Apple ID 只能本机开发签名（appex 能否签未核实）；未签名/ad-hoc 能否加载未核实，不建议赌。替代：菜单栏图标 + 拖拽 + 服务/快捷指令，入口隐蔽但零签名。
- **Windows**：`HKCU\Software\Classes\Directory\shell\...` 每用户注册，无需管理员，也无需签名就能显示；Win11 收在"显示更多选项"里[13][14]。Win11 新菜单需 COM，复杂，不建议。
- **Linux**：Nautilus 脚本目录 `~/.local/share/nautilus/scripts`（无需 root，菜单层级因发行版而异）；Dolphin 用 `~/.local/share/kio/servicemenus/*.desktop`；Thunar 用 `uca.xml`；xdg desktop entry 只是启动器，不是右键菜单（版本差异未核实）。
- **托盘坑**：Linux 无传统托盘，主流桌面走 StatusNotifierItem/AppIndicator；GNOME 必须装 "AppIndicator and KStatusNotifierItem Support" 扩展，否则图标不显示[15]；pystray 在 Linux 走 AppIndicator/GTK，通常只有菜单、左键点击不可用[16]；Electron/Tauri 同样依赖该扩展，Wayland 下更不稳[17][18]。
- 授权：PySide6 为 LGPL，闭源分发需满足动态链接条件；PyQt 是 GPL/商业双授权，别混用。

## 5. 打包与签名

| 平台 | 未签名体验 | 用户绕过 | 正式签名 | 备注 |
|---|---|---|---|---|
| macOS | Gatekeeper"无法验证开发者" | macOS 15+：系统设置→隐私与安全性→仍要打开；更早可右键打开[22]；或 `xattr -d com.apple.quarantine` | $99/年 + 公证 | PyInstaller 需逐二进制签名 |
| Windows | SmartScreen"Windows 已保护你的电脑"（仅下载文件） | 更多信息→仍要运行；受策略管控时不能绕 | OV/EV 证书或 Azure Trusted Signing | onefile 易被 Defender 误报 |
| Linux | 无系统级拦截 | AppImage 需 libfuse2，或 `--appimage-extract`[23] | 无 | deb 需 root 安装 |

- **macOS**：PyInstaller 产物是 `.app`，用 `--windowed --codesign-identity`；onefile 解压到临时目录，公证/杀软更易出问题，建议 onedir[19]。PySide6 framework 多，常见失败是嵌套 dylib 未签名导致公证不通过[20]；每个 Mach-O 都要 Developer ID + hardened runtime + timestamp。
- **Windows**：SmartScreen 只看 Mark-of-the-Web，U 盘/共享盘可能不触发，但 Defender 仍可能误报 onefile[21]。Inno Setup 装到 `%LOCALAPPDATA%` 可免管理员，但 WinFsp 驱动仍要管理员。
- **Linux**：AppImage 最省事，但 Ubuntu 22.04+ 默认无 libfuse2[23]；deb 最稳但要 root；单文件二进制启动慢；Flatpak 对 FUSE 挂载不友好。

## 6. 推荐组合（分阶段）

- **阶段 0（1–2 周）**：Python 3.12 + PySide6 + PyNaCl/cryptography；per-file vault、Argon2id、XChaCha20-Poly1305 分块、AES-SIV 文件名；CLI 内核 + 最小 GUI；三平台跑 1 万文件/10 GB 压测。
- **阶段 1（4–6 周，MVP）**：pystray 托盘 + 解锁/自动锁定 + 应用内浏览/预览/导出；PyInstaller onedir + 安装说明；不做右键。
- **阶段 2（2–3 周）**：Windows HKCU；Linux Nautilus/Dolphin 菜单；macOS 菜单栏 + 拖拽，Finder Sync 留到对外分发。
- **阶段 3（可选）**：虚拟盘。为自有格式写 FUSE/WinFsp 适配层：Linux 先跑通，Windows 需 WinFsp，macOS 视 MDM（禁 kext 就放弃）；约 3–6 月。
- **阶段 4（对外分发）**：Apple Developer Program + 公证；Windows 代码签名；自动更新。

**一句话**：MVP 不做挂载/右键，先把加密目录 + 应用内访问 + 托盘做稳；挂载和右键是加分项，不是核心价值。

## 7. 风险清单

1. macOS 挂载依赖 kext/降安全等级，MDM 常禁 —— **不可回避**（若坚持挂载）。
2. macOS 原生右键 = Finder Sync + $99/年 + 公证 —— **不可回避**（若坚持原生右键）。
3. 共享盘并发冲突，vault 可被同事删除 —— 可缓解，**不可完全回避**。
4. 明文临时文件、崩溃残留、备份/同步外泄 —— 可缓解，**不可完全回避**。
5. 同事有管理员/root 或物理访问 —— **不可防御**；加密只防"诚实但好奇"的同机用户，解锁期间同账号仍可读。
6. 未签名被 Gatekeeper/SmartScreen/EDR 拦截 —— 签名/文档可缓解。
7. 密钥丢失/离组导致数据不可恢复 —— **管理上不可回避**，需托管/恢复流程。
8. 自研格式与文件名加密的实现缺陷 —— 通过复用成熟原语 + 外部审计缓解。
