# 文件保险箱 · 技术方案（v0.2 · 已确认）

> 配套：[需求说明书.md](需求说明书.md)（给用户确认）、[参考-技术调研.md](参考-技术调研.md)（选型调研，含来源链接）。
> 本文档给实现用，包含格式、密码学、崩溃安全、平台细节和测试计划。
>
> **v0.2 变更（2026-11-01 需求确认后）**
> - 不做 Linux 桌面 / 命令行版（服务器不存数据）；核心保持跨平台，以后补 CLI 成本很低。
> - 共用电脑改为**每人一个独立系统账户**：审计的 `actor` 改为自动记录当前系统账户，不再手选；解锁时把明文目录权限收紧到当前账户。
> - 保险箱建议 ≤ 20 GB（向导按磁盘/文件数给建议）；已确认最大单文件 < 1 GB，峰值额外空间 < 2 GB。
> - 界面确定 PySide6（安装包约 200 MB）；Windows 真机用组里共用电脑；macOS 右键用"快速操作"，不做 Finder Sync。

## 0. 设计原则（按优先级）

1. **数据不丢** > **安全** > **好用** > **体积小**。
2. **永不先删后写**：任何删除动作之前，对应副本必须已经写盘、fsync、并校验通过。
3. **原子写**：所有元数据和文件落盘都走 `tmp → fsync → rename → fsync(dir)`。
4. **可恢复**：任何一步断电/被杀，重启后都能判定状态并继续或回滚，两个方向都安全。
5. **不联网、无遥测、无远程日志**。
6. **复用成熟密码原语**，不自创算法；格式保持简单、可审查。
7. **默认失败安全**：不确定的时候宁可报错停下，也不猜着继续。

## 1. 总体架构

```
文件保险箱/
├── core/                 纯 Python，无界面，可单测、可被 CLI/GUI 复用
│   ├── crypto.py         Argon2id、HKDF、AEAD、（旧版）恢复密钥编解码
│   ├── questions.py      密保问题：预设、答案规范化、校验
│   ├── header.py         header.json 读写（原子）、状态枚举
│   ├── manifest.py       SQLite 元数据：加密路径、哈希、时间戳、状态
│   ├── transform.py      逐文件流式加/解密、校验、原子替换
│   ├── vault.py          状态机：create / unlock / lock / recover / verify
│   ├── journal.py        追加写恢复日志 + 恢复判定
│   ├── audit.py          审计日志（JSONL + 哈希链）
│   ├── space.py          磁盘空间预估与检查
│   └── fsutil.py         路径/mtime/权限/平台差异/长时间运行任务
├── cli/                  命令行：lock / unlock / status / verify / audit
├── gui/                  PySide6：主窗口、向导、进度、托盘、审计、设置
├── platform/             Windows 注册表右键、macOS 快速操作安装、空闲检测
├── tests/                单元 + 崩溃注入 + 数据一致性 + 性能
├── packaging/            PyInstaller spec、Windows 构建脚本、dmg/zip、CI
└── docs/                 本文档、需求、草图、安装说明
```

**依赖**：`PySide6`（LGPL）、`cryptography`、`argon2-cffi`；开发/构建：`pytest`、`pyinstaller`。
**最低系统**：macOS 13+（Intel / Apple Silicon）、Windows 10 1809+ / 11 x64。

## 2. 盘上格式

保险箱 = **用户选择的那个文件夹本身**，路径不变：

```
患者影像-2024/                    ← 已上锁状态
├── .vault/
│   ├── header.json              明文外壳，不含秘密：格式版本、KDF 参数、状态、包裹后的密钥
│   ├── manifest.db              SQLite，文件名在这里是密文
│   ├── blobs/<uuid>             每个文件一份密文，文件名是随机 UUID
│   ├── journal.jsonl            恢复日志（追加写，带序号和 CRC）
│   └── tmp/                     临时文件（与目标同盘，保证 rename 原子）
└── 如何解锁.txt                 给同事看的说明（不含敏感信息，可在设置里关闭）
```

已解锁状态：原文件夹恢复成普通目录树，**`.vault/` 仍然保留**（它的 manifest 继续用于重新上锁和增量判断；里面仍是密文/无秘密内容）。

### header.json 字段

```jsonc
{
  "format": "fdv1",
  "vault_id": "8f3c…",            // UUID
  "created_at": "2026-10-28T10:00:00+08:00",
  "kdf": { "name": "argon2id", "salt": "b64", "m": 65536, "t": 3, "p": 1 },
  "wrapped_vault_key_password": "b64(AEAD)",   // AAD = vault_id|"pw"
  "wrapped_vault_key_recovery": "b64(AEAD)",   // AAD = vault_id|"recovery"
  "recovery_fingerprint": "K4TQ-…-6VLU",       // 前4+后4组，给人核对
  "recovery_generated_at": "…",
  "state": "LOCKED",              // LOCKED / UNLOCKING / UNLOCKED / LOCKING / INCONSISTENT
  "state_since": "…",
  "file_count": 12340,
  "total_bytes": 925714…
}
```

- header **原子写**；`state` 变化必须先落盘再做真正动作，这样断电后能知道"当时准备干什么"。
- 文件权限：Unix `0600`，目录 `0700`。

### manifest.db（SQLite）

```sql
CREATE TABLE files(
  id          INTEGER PRIMARY KEY,
  uuid        BLOB NOT NULL UNIQUE,      -- 16 字节，用于派生 per-file 密钥 / 命名 blob
  path_ct     BLOB NOT NULL,             -- 加密后的相对路径（含文件名）
  path_nonce  BLOB NOT NULL,
  size        INTEGER NOT NULL,
  mtime_ns    INTEGER NOT NULL,
  mode        INTEGER,
  sha256      BLOB NOT NULL,             -- 原始明文哈希（解锁校验 + 增量判断）
  chunk_size  INTEGER NOT NULL,
  is_dir      INTEGER NOT NULL DEFAULT 0,
  state       TEXT NOT NULL              -- OK / PENDING_UNLOCK / PENDING_LOCK
);
CREATE TABLE meta(key TEXT PRIMARY KEY, value TEXT);
```

- **文件名加密**：`path_ct = AEAD(HKDF(K,"name"), path_nonce, rel_path)`，AAD = uuid。文件名、目录名都不以明文出现在盘上；blob 文件名是随机 UUID。
- 会泄漏的信息：文件数量、每个文件大小、目录总大小、大致修改时间（mtime 存明文是为了解锁时还原）。这在可接受范围内，文档里写明。
- `sha256` 是**明文哈希**，不泄漏内容，但能用于"是否被改过"。

## 3. 密码学设计

### 3.1 密钥层级

```
用户密码（6 位数字）──Argon2id(salt)──► KEK_pw ──AEAD 解包──► vault_key K (32B 随机)
密保答案 1 ──规范化──Argon2id(salt1)──► KEK_q1 ──AEAD 解包──┤
密保答案 2 ──规范化──Argon2id(salt2)──► KEK_q2 ──AEAD 解包──┤
密保答案 3 ──规范化──Argon2id(salt3)──► KEK_q3 ──AEAD 解包──┤
（仅旧版）恢复密钥 R ──HKDF──► KEK_rec ──AEAD 解包──┘
K ──HKDF("file", uuid)──► 每文件子密钥
K ──HKDF("name")───────► 文件名加密密钥
K ──HKDF("manifest")───► manifest 内其他敏感字段
```

- **Argon2id**：默认 `m=64MiB, t=3, p=1`，创建时按机器校准到约 0.5–1 秒；参数写入 header。
- **密码**：任意 6 位数字（`core/passwords.py`）。只在「设新密码」时检查规则，旧版保险箱的复杂密码照样能解锁。
- **密保问题**（格式版本 2，`core/questions.py`）：新建保险箱时必须设 3 个、互不重复的问题（预设列表里选）。
  每个答案各自派生一把 KEK、包裹同一个 K，所以**答对任意一个**就能解开；header 的 `security_questions[]`
  只存 `{q, kind, kdf(含独立 salt), wrapped}`，不存答案。答案先规范化再派生：
  NFKC + 去空格标点 + 不分大小写；日期类统一成 `YYYYMMDD`（只认年在前的写法）；城市类去掉末尾「市」。
  AEAD 的 AAD 为 `fdv1|<vault_id>|question:<序号>`。
- **答错计次**：解锁 / 重置时答错和输错密码一样累加 `failed_attempts`，第 6 次起延迟 10–60 秒。
- **改密码 / 用密保重置密码**：解包 K → 用新 KEK 重新包裹 → 只重写 header，**数据不动**；密保不受影响。
- **修改密保问题**：需当前密码；三个问题全部重新包裹，旧答案立即失效。旧版保险箱设好密保后，恢复密钥随之作废。
- **兼容**：还带恢复密钥、没有密保的 header 继续写成版本 1（旧版软件能打开）；有密保的写成版本 2，旧版软件会提示升级。
- **安全取舍（用户确认）**：6 位数字只有 10⁶ 种，生日 / 城市类答案也容易被查到或枚举。界面上的输错延迟挡得住
  守在电脑前乱试的人，但挡不住把 `.vault` 整个拷走后离线慢慢试的人（单核约几天，GPU 更快）。
  所以保险箱文件夹要放在别人不能随手拷走的位置，密保尽量选组外人查不到答案的问题。
- **（旧版）恢复密钥 R**：20 字节 CSPRNG → Base32（去掉填充）= 32 字符，按 4 字符一组显示：`K4TQ-9WPE-…`。
  新建保险箱不再生成；旧保险箱仍可用它解锁 / 重置密码。
- **二期独立账号**：header 增加 `recipients[]`（每人一把 X25519 公钥，`crypto_box_seal` 包裹同一个 K），数据格式不变，可平滑升级。

### 3.2 文件加密

- 算法：**XChaCha20-Poly1305**（`cryptography` 的 `ChaCha20Poly1305` 用 12 字节 nonce；如需 24 字节 XChaCha 可经 PyNaCl）。二选一在 M1 定稿，接口不变。
- **分块**：4 MiB 一块；`nonce = 4B 0 || 8B 块号(大端)`；每个文件用独立子密钥 `K_f = HKDF(K, salt=uuid, info="file-v1")`，所以计数器不会跨文件碰撞。
- **AAD**：`format_version | uuid | 块号 | 是否最后一块` → 防止块重排、截断、跨文件嫁接。
- **头部**：明文格式 `"FDB1" | 版本 | 块大小 | 块数`（无秘密）。
- **完整性**：manifest 里的 `sha256` 是明文哈希，解锁时逐文件比对；AEAD 负责密文完整性。

### 3.3 为什么不用 age / 7z / 整包容器

| 方案 | 不适合的原因 |
|---|---|
| age | 整文件流式，无法随机读/增量；没有文件名加密；适合导出/备份，不适合日常文件夹 |
| 7z / ZIP | 每次改动要整体重压；解压后明文裸露 |
| 单文件加密容器（VeraCrypt 式） | 固定大小、每次写入大范围重写；要驱动/管理员 |
| Cryptomator / gocryptfs 思路 | 方向正确（per-file vault），但依赖 FUSE 或 Java，三平台体验不一致；我们按同样思路自研纯校 Python 实现 |

参考调研：`参考-技术调研.md` §2。

## 4. 状态机与崩溃安全（核心）

### 4.1 状态

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| LOCKED | 全部为密文 | unlock |
| UNLOCKING | 正在解密 | 继续 / 回滚到 LOCKED |
| UNLOCKED | 全部为明文 | lock |
| LOCKING | 正在加密 | 继续 / 回滚到 UNLOCKED |
| INCONSISTENT | 检测到未知混合状态 | 进入恢复向导，逐文件判定 |

`state` 只描述"正在做什么"，**不描述每个文件**；每个文件的真实状态由文件系统 + manifest + journal 决定。

### 4.2 解锁一个文件（安全顺序）

```
1. 从 manifest 取记录，读 blobs/<uuid>，逐块 AEAD 校验并解密
2. 写入同目录 tmp/<uuid>.part，边写边 fsync
3. 校验：sha256(解密结果) == manifest.sha256
4. 还原 mtime_ns / mode
5. 原子 rename tmp → 目标相对路径；fsync 父目录
6. journal: FILE_UNLOCKED_OK(uuid, sha256)
7. 删除 blobs/<uuid>（此时明文已是校验过的唯一副本；journal 已记录）
```

**不变量**：任何时刻，每个文件要么是"已校验的密文"，要么是"已校验的明文"，不存在两边都没有完整副本的时刻。

### 4.3 上锁一个文件（镜像顺序）

```
1. 读明文，逐块加密，写 blobs/<uuid>.part + fsync
2. 读回密文做 AEAD 校验（或依赖写入时的 tag）
3. 校验：明文 sha256 与计算值一致
4. rename .part → blobs/<uuid>；fsync 父目录
5. journal: FILE_LOCKED_OK(uuid)
6. 删除明文；journal: PLAINTEXT_REMOVED(uuid)
```

### 4.4 恢复判定（启动时）

| 文件系统里看到 | manifest/journal 说 | 处理 |
|---|---|---|
| 明文存在且哈希匹配 | PENDING_LOCK | 继续上锁 |
| 密文存在且能解密 | PENDING_UNLOCK | 继续解锁 |
| 只有 `.part` | — | 丢弃 `.part`，按另一份重做 |
| 明文和密文都不在 | — | **不可能发生**（触发 INCONSISTENT，停止一切操作并提示） |
| 两者都在且都校验通过 | — | 删掉多余的一份（优保守：保留密文，删明文，除非在 UNLOCKING 状态） |

- journal 每条记录 `seq | ts | op | uuid | 结果 | crc32`，按批 fsync（每 64 条或 1 秒），**恢复逻辑是幂等的**，不依赖 journal 一定完整。
- 恢复过程本身也遵循同一顺序，可再次中断再恢复。

### 4.5 用户可见的三种入口

- 正常开始前：`LOCKED → UNLOCKING → UNLOCKED`（或失败时回滚）
- 断电重启：`INCONSISTENT` → 恢复向导（继续 / 回滚）
- 用户取消：停止 + 反向回滚（解锁取消 → 把已解密的重加密；上锁取消 → 把已加密的解密）

## 5. 磁盘空间与性能

- **峰值额外空间** ≈ `2 × 最大单文件 + journal + 少量元数据`（逐文件转换；同一时刻最多一个文件的明文 + 一个密文/临时副本）。已确认最大单文件 < 1 GB → 峰值 < 2 GB，磁盘剩 < 10% 也能跑；开始前仍会检查并给出具体数字。
- 开始前检查：`free ≥ 2 × max_file + 256 MB`，否则提前拒绝并给出具体数字；运行中如果空间不够，安全停止并提示。
- **性能目标**：SSD ≥ 150 MB/s；1 万个小文件（10 GB）< 5 分钟；单文件 4 MiB 分块支持暂停/断点。
- **小文件优化**：DICOM 小文件多，manifest 事务按批提交（每 64 个文件一次），避免 SQLite 每文件 fsync；实测后再调。
- **进度**：按字节（主）+ 文件数（辅）+ 瞬时速度 + 剩余时间；UI 至少每 200ms 更新一次。

## 6. 审计日志

- 位置（**不在保险箱里**，否则要先解锁才能写日志）：
  - macOS：`~/Library/Application Support/文件保险箱/audit.jsonl`
  - Windows：`%APPDATA%\文件保险箱\audit.jsonl`
- 权限 `0600`；追加写；每条记录包含：`ts / event / actor / vault_path / vault_id / detail / result / app_version / hostname / prev_hash / hash`。`actor` 自动取当前系统账户名（每人独立账户后可信度较高），不再由使用者手选。
- 事件：`CREATE / UNLOCK / LOCK / AUTO_LOCK / UNLOCK_FAILED / ABORT / RECOVER / CHANGE_PASSWORD / REGENERATE_RECOVERY / DELETE_VAULT / EXPORT_AUDIT / VERIFY`。
- `hash = SHA256(prev_hash + 规范化 JSON)`，形成哈希链；"校验完整性"能发现简单篡改。局限：本机管理员可以整链重写；密码共用导致只能证明"谁在操作"，不能证明"谁有权操作"——所以是**半弱审计**，导出 CSV 时在文件头写明。
- 导出 CSV：时间、操作人、操作、保险箱、结果、详情；文件本身按敏感文件处理。
- 保留 12 个月（可配置），清空需密码且本身记一条日志。

## 7. 平台实现要点

### 7.1 GUI（PySide6）

- 主窗口 + 托盘 `QSystemTrayIcon`（macOS 菜单栏 / Windows 右下角）。
- 单实例：`QLocalServer` + `QLocalSocket`（第二次启动把参数交给已运行实例，比如右键菜单传进来的路径）。
- 长任务放 `QThread`，UI 不卡；暂停用 `threading.Event`。
- 关闭窗口 = 最小化到托盘；退出 = 先上锁再退出（若上锁失败，明确询问用户）。
- 提示语全部中文、不带技术术语；错误信息给"人话 + 展开详情"。
- 首次启动向导：解释风险（明文可见、无签名、备份）、建议开系统磁盘加密；检测到仍是共用账户时提醒先建独立账户。
- 解锁时把明文目录/文件权限收紧到当前账户（Unix `0700/0600`，Windows 用 `icacls` 只授当前用户），上锁后恢复原权限；配合独立账户防止其他账户读取。

### 7.2 自动上锁

- macOS：`IOHIDSystem` 的 `HIDIdleTime`（ctypes）读空闲秒数。
- Windows：`GetLastInputInfo`（ctypes）。
- 触发后先弹 60 秒倒计时通知（可取消）；有文件正在被占用时中止并提示，不硬来。
- P1：锁屏/休眠事件（macOS distributed notification、Windows session change）也触发上锁或至少提醒。
- 兜底：退出软件、系统关机前（能 hook 就 hook，不能就提示）。

### 7.2.1 外部程序"正在使用"标记（和 CT 脱敏工具联动）

脱敏这类长任务只在读写文件的一瞬间打开文件，上锁前的占用检查（lsof / 共享冲突）查不到；
中途上锁会让它读不到原始数据，或把映射表重新以明文写回已上锁的文件夹。约定：

- 外部程序运行期间写 `.vault/in-use-<工具>.json`（在 `.vault` 里，不加密、不出现在用户文件夹）：
  `{"tool", "active", "pid", "host", "started_at", "heartbeat"(Unix 秒), "what"}`；
  每 30 秒刷新 `heartbeat`，结束时把 `active` 写成 `false`（脱敏工具承诺不删任何文件，所以不删标记）。
- 有效标记 = `active is true` 且心跳在 180 秒以内（允许 60 秒时钟误差）。外部程序崩溃后最多 3 分钟自动失效。
- `Vault.lock()` 在核对密码前先查标记，有效就抛 `InUseError`，状态和文件都不动；
  GUI 自动上锁跳过这些保险箱，卡片显示"正在使用，用完前不自动上锁"；标记失效后人还没回来就照常自动上锁。
- `status()` 多一个 `in_use_by` 字段，命令行 `status` 会显示。
- 实现：`core/inuse.py`（只读、不需要密码）；对端实现在 `脱敏小软件/deid/vault_link.py`，
  两边各有测试，脱敏工具的测试会直接用本项目的 `core/inuse.py` 读它写的标记。

### 7.3 Windows 右键菜单（免费）

- `HKCU\Software\Classes\Directory\shell\FileSafeLock`，`command = "…\文件保险箱.exe" lock "%1"`；`FileSafeUnlock` 同理。
- 不需要管理员；Win11 默认收在"显示更多选项"（可在安装说明里告诉用户 Shift+F10 或改注册表恢复旧菜单，不改也行）。
- 卸载时清理这两个键。

### 7.4 macOS 右键（P1，替代方案）

- **不做** Finder Sync Extension（需要 Apple Developer Program，99 美元/年 + 公证）。
- 做一个 Automator「快速操作」`.workflow`（Run Shell Script 调 CLI 的 `lock "$@"`），首次运行 `安装右键菜单.command` 拷到 `~/Library/Services/`，然后 `killall Finder`。
- 风险：macOS 版本差异、Gatekeeper 对待 `.workflow` 的行为需要在真机验证（M4）。
- 兜底入口：拖到菜单栏图标、主窗口选择文件夹、终端命令。

### 7.5 路径与文件系统兼容

- macOS 文件名是 NFD、Linux/Windows 是 NFC → **只在 macOS 上处理**，保存时统一 NFC，还原时按原样。
- Windows：保留名（CON、PRN…）、结尾空格/点、大小写不敏感冲突、260 字符路径限制 → 创建时扫描并拒绝/提示；读写用 `\\?\` 前缀绕过限制。
- 符号链接：默认**跳过并记录**（避免越界加密），界面提示跳过了哪些。
- 硬链接：各自当独立文件处理（内容重复），文档写明。
- 扩展属性 / Finder 标签 / Windows ADS：MVP 不保留（文档写明）；mtime、mode 保留。
- 权限不足、文件被占用：不强行改，报错 + 回滚 + 指出具体文件。

### 7.6 打包与分发

| 平台 | 形式 | 说明 |
|---|---|---|
| macOS | PyInstaller **onedir** → `文件保险箱.app` → zip（可选 dmg） | 不签名：首次右键"打开"；文档给 3 步图文 |
| Windows | PyInstaller **onedir** → zip（可选 Inno Setup 装到 `%LOCALAPPDATA%`，免管理员） | SmartScreen 首次"仍要运行"；onefile 容易被 Defender 误报，故用 onedir |

- 安装包预计 150–250 MB（PySide6 体积决定）。

## 8. 测试计划

### 8.1 单元测试（core，纯 Python）

- crypto：KDF/包裹/解包、错误密码、恢复密钥编解码、AAD 篡改检测。
- header：原子写、字段校验、版本升级、损坏处理。
- manifest：`path_ct` 加解密、大目录（10 万条）、事务、崩溃后一致性。
- transform：分块边界、空文件、0 字节、超大文件、只读文件、mtime 还原。
- fsutil：NFC/NFD、Windows 保留名、长路径、符号链接。

### 8.2 崩溃注入（最关键）

- 实现：在关键步骤埋 `crash.point("步骤名")`，环境变量 `FDVAULT_CRASH_AT="步骤名=第几次"` 命中时
  直接 `os._exit(70)`，模拟断电/强杀。
- 覆盖 13 个注入点：解锁 7 个（密文校验后 / rename 前 / rename 后 / manifest 提交前 / 提交后 /
  删 blob 前 / 删 blob 后）、上锁 6 个（写 blob 前 / rename 后 / 提交前 / 提交后 / 删明文前 / 删明文后）。
- 恢复逻辑设计成**幂等**，且**正常操作与恢复共用同一套 finalize 代码**，所以日常路径本身就是恢复路径。
- 断言：每个文件 SHA256、mtime（纳秒）、权限位、目录结构完全一致；**0 丢失、0 损坏**；
  上锁后扫描无明文内容/文件名残留。

### 8.3 数据一致性 / 安全

- 随机目录树（中文、emoji、空格、深路径、空目录、重复内容）全量 SHA256 比对。
- 篡改测试：随机改 blob 一个字节 → 必须报错且不产出错误明文；改 header → 必须拒绝。
- 明文残留扫描：解锁→上锁后，在整个分区按已知内容片段搜索（排除日志）。
- 暴力猜测限速测试；恢复密钥错误处理。

### 8.4 性能

- 目标：1 万文件 / 10 GB，上锁、解锁各 ≤ 5 分钟（已用实测验证，见 8.6）。
- 单文件上限按已确认的 < 1 GB 设计；更大的单文件（4 GB）不再作为本版测试项。
- 10 万文件 / 100 GB 外接盘在 M4 用真实试点数据量补测。
- 记录吞吐量；峰值内存不单独测量（流式处理，不整文件读入内存）。

### 8.5 跨平台

- GitHub Actions：`macos-latest`、`windows-latest` 跑单元 + 构建 + 冒烟测试（CLI 层）。
- **最终人工验收在你们的 Windows 真机上做**（GUI、右键菜单、托盘、真正的断电）。

## 13. M1 实现记录（2026-11-01）

实现过程中对 v0.2 方案的补充与差异：

1. **正常路径即恢复路径**：上锁/解锁的落盘循环直接调用恢复用的 `_finalize_lock` / `_finalize_unlock`，
   避免"恢复代码从没被日常路径执行过"的风险。
2. **状态以 manifest 为准，journal 只做诊断**：恢复不依赖 journal；journal 早期版本记录过明文路径，
   已修正为只记 uuid（否则上锁后 metadata 泄漏文件名）。
3. **每 32 个文件一批提交**：先加密/解密并 fsync → 提交 manifest（SQLite 事务）→ 再删旧副本；
   崩溃后按"明文是唯一可信来源"（上锁）/ "明文优先、缺则用密文重建"（解锁）重新对齐。
4. **跨进程互斥**：`.vault/instance.lock` + `fcntl.flock`（Windows 用 `msvcrt.locking`），
   防止 GUI 与命令行同时操作；进程崩溃时内核自动释放，不会留下死锁。
5. **manifest 丢失保护**：解锁/校验前检查 manifest 存在且文件数与 header 一致；
   上锁时若 manifest 被删，可从明文树重建（代价是 uuid 重新生成）。
6. **KDF 现场校准**：创建时测速选 Argon2id 迭代次数（目标 ~0.7 秒，m=64 MiB 起），参数写进 header，
   换机器也能解开；测试可用 `FDVAULT_KDF_FAST=1`。
7. **目录权限**：`.vault` 及子目录 `0700`，header/manifest/blob `0600`；解锁时先以 0600 写临时文件，
   再 chmod 回原权限、恢复原始 mtime（纳秒）。
8. **目录结构**：`core/`（crypto / header / manifest / transform / vault / fsutil / lockfile / audit /
   journal / crash）、`cli/`、`tests/`（77 个）、`scripts/`（stress_crash / bench）、`reports/`（测试原始数据）。
9. **性能结论**：1 万文件 / 9.3 GB 解锁 44 秒、上锁 53 秒（约 190–220 MB/s，上锁含文件占用预检）；
   原地解锁删密文 ⇒ 每次上锁全量重写，两个方向耗时接近，这是磁盘紧张下的既定取舍。

## 14. M2 实现记录（2026-11-01）

M2 把 M1 的核心能力包成图形界面，实现要点与对方案的影响：

1. **界面与核心分离**：`gui/` 只依赖 `core/` 的公开接口（`Vault`/`OperationControl`），
   核心不 import 任何 Qt；因此核心测试仍可在无图形环境跑，GUI 自检也可离屏跑。
2. **长任务进后台线程**：解锁/上锁/首次上锁/恢复/校验都走 `VaultOpWorker(QThread)`，
   通过 `progressed/succeeded/failed/cancelled` 信号回主线程；界面只负责展示与按钮状态，
   避免进度期间窗口假死。
3. **暂停 / 取消 / 回滚**：`OperationControl` 在每处理一个文件前 `check()`；
   - 取消后保险箱停在中间态（`UNLOCKING`/`LOCKING`），不假装成功；
   - 界面提供"自动回滚"，复用 M1 的 `recover(rollback=True)`，幂等；
   - 下次打开时若检测到中间态，弹出恢复向导（继续 / 回滚）。
4. **两阶段创建**：向导第 2 步只做 `prepare_new`（生成密钥、写 header、返回恢复密钥），
   第 4 步才 `initial_lock` 真正迁移文件。这样用户可以在"看到恢复密钥之后、开始加密之前"退出，
   `abort_create()` 会清掉半成品，文件夹原样保留。
5. **会话内保存密钥**：解锁后 `MainWindow.sessions[path] = Vault` 持有内存中的密钥，
   自动上锁/托盘"立即上锁全部"可直接上锁，不必再输密码；程序重启后内存密钥消失，
   再上锁需要重新输密码（界面已用提示说明）。
6. **自动上锁的空闲检测**：macOS 用 `ioreg -c IOHIDSystem -d 1 -r` 的 `HIDIdleTime`，
   Windows 用 `GetLastInputInfo` + `GetTickCount64`，Linux 用 `xprintidle`（仅开发用，交付不含）。
   `idle_seconds()` 带 0.8 秒缓存，避免每秒 fork 子进程。
7. **单实例**：`QLocalServer` 命名 socket；第二个进程 `activate_existing()` 发激活消息后退出。
   另有 M1 的 `.vault/instance.lock` 跨进程文件锁兜底，防止命令行与 GUI 同时改同一个保险箱。
8. **审计界面**：直接读 `audit.jsonl`，支持按保险箱筛选、导出 CSV、重算哈希链校验是否被改；
   `WEAK_AUDIT_NOTE` 放在日志窗口左下角「共 N 条 ⓘ」的悬停提示里（界面不再常驻长段说明），导出的 CSV 里照常写入，明确"半弱审计"的边界。
9. **测试策略**：PySide6 的 `QApplication` 在 pytest 解释器退出阶段会偶发崩溃，因此
   GUI 检查放在子进程脚本 `scripts/gui_selftest.py`（离屏、结尾 `os._exit`），
   pytest 里只保留一个子进程调用 + 纯配置测试；截图由 `scripts/gui_screenshots.py` 可重复生成。
10. **版本**：`gui.__version__ = "0.3.1"`；测试数量 134（含 GUI 入口子进程 3 项、安装包/CI 静态检查 10 项），
    GUI 子进程内另有 18 项检查。M3 起进入打包与真机联调。

## 15. M4 进展记录（2026-11-01）

1. **入口补齐**：支持三种"直接把文件夹交给程序"的方式——
   - Windows 右键菜单（`installers/windows/安装右键菜单.ps1`，写 HKCU，传 `%1`）；
   - macOS 拖文件夹到程序图标 / `open -a 文件保险箱 文件夹`（`QFileOpenEvent`）；
   - 命令行 `python run_gui.py <文件夹>`（`folder_arg` 解析，跳过 macOS 的 `-psn_`）。
   三种方式都只做"打开新建向导并预填路径"，不绕过密码和确认步骤。
2. **密码错误节流**：连续错 5 次后每次等 10 秒（递增到 60 秒），计数存在 header 里，重启不清零；
   测试模式（`FDVAULT_KDF_FAST=1`）只 20ms，保证测试速度。
3. **文件占用**：上锁前预检（Windows 共享冲突 / macOS lsof），被占用则不改变状态、直接提示；
   删明文失败（`PermissionError`）也转成可读提示，保险箱留在可恢复的中间态。
   设 `FDVAULT_SKIP_BUSY_CHECK=1` 可跳过（测试/特殊环境用）。
4. **退出自动上锁**：关闭主窗口或菜单栏"退出"时，自动把会话内保险箱逐个锁回；锁不上时提示
   "文件可能被占用"并让用户选择仍退出或取消。启动时对"上次没锁回"的保险箱在状态栏和卡片上提示。
5. **安装包自检**：`gui/selfcheck.py` 提供 `文件保险箱 --selftest`（离屏），验证加密往返、
   状态机、审计链、主窗口、密码框/进度条、图标 6 项；`gui/acceptance_check.py` 提供
   `文件保险箱 --acceptance`，用**默认 KDF 与 4 MiB 分块**跑 9 MiB 大文件、恢复密钥、权限位、
   明文残留扫描 6 项。两者都支持 `--report <文件>`（Windows `--windowed` 程序没有 stdout，
   验收脚本与打包冒烟读这个文件判断成败）。`scripts/build_app.py` 打完后两个都跑，不通过就构建失败。
6. **安装产物**：macOS 一次构建产出 zip（拖拽安装）、dmg（`hdiutil makehybrid` + `convert`，
   避开受限环境不能临时挂载的问题；构建时 verify + 实际挂载检查）、源码 zip（2.5 MB，
   含 core/gui/tests/docs/installers/CI，换机器可复现）。
7. **macOS Finder 快速操作**：`installers/macos/用文件保险箱上锁.workflow`（基于系统
   Run Shell Script action，接收文件夹输入，找到 .app 后 `open -a ...`）+ 双击安装脚本
   `安装快速操作.command`；结构/参数逻辑有 2 个测试兜底，Finder 注册需真机执行。
