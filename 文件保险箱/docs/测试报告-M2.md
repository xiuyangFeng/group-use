## 5. 关键流程验证细节

### 5.1 新建 → 上锁（向导）

1. 选一个含 4 个子目录、多个文件的文件夹；
2. 设 12 位以上密码，`prepare` 阶段生成密钥（Argon2id 校准在正常模式下 ~0.7 s）；
3. 显示恢复密钥（32 位 Base32，4 位一组，可复制）；
4. 进入首次上锁进度页，后台线程执行 `Vault.initial_lock`；
5. 完成后状态 `LOCKED`，文件夹里只剩 `.vault/` 和 `如何解锁.txt`；
6. 退出向导，主窗口自动加入这个保险箱。

验证：状态正确；解锁后 `snapshot()`（相对路径、字节、sha256、mtime、权限）与创建前完全一致。

### 5.2 取消 → 回滚（新增能力）

`OperationControl.cancel_after=2` 让解锁进行到第 2 个文件时取消：

1. 状态保持 `UNLOCKING`（有中间态，不假装成功）；
2. 界面弹"已取消，是否自动回滚？"；
3. 选择回滚 → `Vault.recover(rollback=True)` → 状态 `LOCKED`；
4. 数据逐字节一致；
5. 下次打开界面会看到恢复向导（`ST_` 中间态可继续或回滚，幂等）。

### 5.3 自动上锁

- 设置里可选 5/10/15/20/30/60 分钟，默认 15 分钟；
- 主窗口每秒刷新倒计时，空闲达到阈值自动调用上锁；
- 上锁前弹确认（M2 设计：有未保存工作可点取消，取消后重置计时）；
- 测试用模拟空闲 301 秒验证了"会触发"，真机还需人坐着不动 15 分钟确认一次。

### 5.4 单实例与跨进程互斥

- GUI 用 `QLocalServer` 做单实例：再点图标 → 唤起已有窗口；
- 加密核心另有 `.vault/instance.lock`（flock/msvcrt）兜底：命令行和 GUI 同时操作会报
  "另一个窗口正在操作这个保险箱，请等它结束再试"；
- 注意：测试时用 `exec python -m gui &` 启动，避免外层 shell 的 PID 与 Python 进程不一致，
  否则 kill 外层 PID 会留下真正在跑的进程（排查时遇到过一次）。
