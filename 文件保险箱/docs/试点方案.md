# 真实（脱敏）数据试点方案

> 目的：在正式给全组用之前，用一个**已经脱敏**的小文件夹完整走一遍流程，
> 收集真实使用中的问题，作为 M4 验收和交付的证据。全程不碰真实患者数据。

## 1. 试点范围（建议）

| 项目 | 建议 |
|---|---|
| 数据 | 已脱敏的伦理审查材料 / 教学用病例 / 已发表论文的原始数据，**不要用真实患者身份信息** |
| 大小 | 1 个文件夹，≤ 1 GB，≤ 1000 个文件（先用小的，成功后再加量） |
| 时长 | 1 周（覆盖"每天解锁—上锁"和一次"连续 3 天不锁"的异常情况） |
| 人员 | 1 名操作人（熟悉流程的组员）+ 1 名验收人（导师或组里另一位） |
| 机器 | macOS 一台 + Windows 共用电脑一台（两个平台都试点） |

## 2. 准备（试点前）

1. **脱敏**：把姓名、住院号、身份证、联系方式等替换或删除；文件里搜一遍"姓名/住院号/电话"确认干净；
2. **备份**：把要试点的文件夹原样复制一份到移动硬盘/另一台机器（试点结束前不删）；
3. **记录基线**：记录文件夹总大小、文件数、随机抽 3 个文件的 SHA256 和修改时间；
4. **清磁盘**：确认剩余空间 > 最大单文件 × 2 + 1 GB；
5. **安装**：按 [Windows](../installers/windows/安装说明.md) / [macOS](../installers/macos/安装说明.md) 安装；
6. **跑自动验收**：Windows 右键 `验收自检.ps1`；macOS 跑 `--selftest` 和 GUI 自检。

## 2.5 先彩排一次（强烈建议）

在碰真实数据前，先跑一遍假数据彩排（不读取你的任何文件，全程用临时目录）：

```bash
python scripts/pilot_rehearsal.py
# 看到 PILOT REHEARSAL PASS：8 步全部通过 即可
```

它会演练：建库 → 解锁/上锁 → 改文件 → 恢复密钥重设密码 → 文件占用时中止 → 审计导出 → 明文残留扫描 → 最终校验。
结果在 `reports/pilot-rehearsal.json`，可以贴进试点记录。

## 3. 试点步骤（操作人照做）

| 天 | 动作 | 要记录什么 |
|---|---|---|
| D1 | 建保险箱：选中试点文件夹 → 设密码 → **抄恢复密钥** → 首次上锁 | 耗时、报错、磁盘峰值、恢复密钥存放位置 |
| D1 | 解锁 → 打开 2–3 个文件 → 修改一个文件保存 → 上锁 | 改动是否保留、耗时 |
| D1 | 故意输错 1 次密码，再输对 | 是否有清楚提示 |
| D2–D4 | 每天正常解锁使用、用完上锁；其中一天离开 15 分钟以上，确认自动上锁 | 自动上锁是否触发、倒计时是否对 |
| D4 | 拔电源/强制关机演练（可选，先确认有备份）：上锁到一半断电 → 重启 → 恢复 | 恢复向导是否给出继续/回滚，数据是否完整 |
| D5 | 退出程序（不手动上锁），观察是否自动锁回；重新打开看"上次没上锁"提示 | 提示是否出现 |
| D6 | 用 Excel 占用一个文件时点上锁，确认中止并提示；关掉 Excel 再锁 | 提示是否清楚、数据是否完好 |
| D7 | 导出审计 CSV（用 Excel 打开确认中文不乱码）、校验哈希链；在另一个系统账户里访问保险箱文件夹 | 权限是否被拒绝、审计记录是否完整 |

## 4. 恢复密钥与密码管理

- 密码：组内当面告知，不写进微信/邮件；
- 恢复密钥：打印一份，放导师抽屉，和密码分开；
- 试点期间**不要**换密码/重新生成恢复密钥，除非专门测试这一项。

## 5. 出错怎么办（按顺序）

1. 不要删 `.vault/`、不要手工改里面的文件；
2. 记下屏幕提示（截图）、时间、你刚才做什么；
3. 打开程序日志（`gui.log`）复制最后 20 行；
4. 重新打开程序，点 **恢复**，选"继续"或"回滚到已上锁"；
5. 把以上信息发给维护人；如果是"打不开/闪退"，先用备份顶一下。

## 6. 试点成功的标准

- 13 条验收里，试点相关的手工项（2、8、9、11、13、14）全部打勾；
- 连续 5 个工作日没有出现"文件丢失/打不开/恢复失败"；
- 操作人能在 3 分钟内完成一次"解锁→改文件→上锁"；
- Windows 和 macOS 都能独立完成整个流程；
- 审计记录能看出"哪个账户、什么时候、做了什么"。

## 7. 试点结束后

1. 把试点数据**上锁**，并把备份保留至少 1 个月；
2. 填写[验收记录表](验收记录表.md)，连同审计 CSV、日志一起归档；
3. 反馈问题按"影响数据安全 / 影响使用 / 小瑕疵"分类，决定是否修；
4. 确认最终产品名字后再做正式推广（安装说明、快捷方式、桌面图标统一改名）。
