# CT 数据脱敏工具

把"每个子文件夹一个患者"的 CT DICOM 数据批量脱敏，输出可以发给外部做分割/标注的数据，并在本地留一份映射表。

## 使用（Windows）

1. 双击 `CT_Deid.exe`
2. 选择三个路径：
   - **原始数据文件夹**：里面每个子文件夹是一个患者（子文件夹内可以有多层目录）
   - **输出文件夹**：脱敏后的数据，发给别人的就是这个文件夹
   - **映射表**：`.xlsx`，记录 编号 ↔ 原患者。已存在就继续追加，同一患者（按患者 ID）沿用原编号
3. 点 **开始脱敏** → 弹窗确认编号分配 → 等待完成 → 查看日志

> 映射表和日志里有患者信息，**只能留在本地**。软件会拒绝把它们放进输出文件夹或原始数据文件夹。

## 使用（Mac）

双击 `run_mac.command`。第一次运行会自动在本文件夹建一个 `.venv-run` 并安装依赖（需要联网，约 1 分钟），以后双击直接打开。
- 如果提示"无法打开，因为来自身份不明的开发者"：右键 → 打开 → 打开（只需一次）
- 需要先从 python.org 装 Python 3.12（系统自带的或 Anaconda 的 Python 也可以，只要带 tkinter）
- 不要直接用系统的 `python3 app.py` 运行，那样会提示缺少依赖

### 数据安全承诺：软件没有任何删除功能

- **原始数据只读**：只打开读取，从不写入、移动、改名或删除。自动测试会在处理前后对每个原始文件做 SHA256 校验，确认逐字节不变
- **不覆盖任何已有文件**：输出里某个患者文件夹已存在就跳过；探查报告重名时会拒绝保存；日志文件名自动加序号
- **写入失败的文件不删除**：留下带 `.part` 后缀的未完成文件，并在日志里注明（不要把它发出去）。续跑时会把它补写完整（只有本软件自己写到一半的 `.part` 临时文件会被重写，`.dcm` 文件永不覆盖）
- **映射表**：每次运行前，先复制一份到旁边的 `映射表备份/` 文件夹，然后再追加新行，历史版本都在
- 源代码里没有任何删除调用（`unlink`、`rmtree`、`os.remove` 等），自动测试会检查这一点

输出结构：

```
输出文件夹/
  P0001/
    T1/                ← 时间点：按检查日期先后编号，同一天的检查算一个时间点
      S01/0001.dcm …   ← 序列：按检查时间、序列号排序；序列内按 InstanceNumber 排序
      S02/…
    T2/                ← 同一患者的第二次检查（随访等）
      S01/…
  P0002/
    T1/…               ← 只有一次检查的患者也有 T1 层，结构统一
```

- **同一患者的识别**：两个原始文件夹的患者 ID 相同，就视为同一个人的不同检查，给同一个编号，再按检查日期分成 T1、T2……
- 输出里不含任何日期，只保留先后顺序。每个 T 对应哪天，记录在映射表的"时间点"列里，例如 `T1=2024-03-03; T2=2024-04-04`
- 建议用映射表核对一下：同一个编号下几行的患者姓名应当是同一个人
- v5 及以前的版本输出是 `P0001/S01/…`（没有 T 层）。新版本不会往这种旧结构的文件夹里继续写，**请换一个新的输出文件夹**。编号由映射表决定，不会变；旧版映射表会自动补上"时间点"列

## 处理记录（以前处理过哪些数据）

每次脱敏和结构探查都会自动留一条记录。下次打开软件时：
- 自动填好**上次的三个路径**，日志框里显示上次的概况（什么时候、处理了哪个文件夹、结果、写出多少文件）。上次没处理完的话，直接点"开始脱敏"就会接着做
- 换一批新数据时，重新选原始数据文件夹，输出文件夹会跟着换；**映射表建议一直用同一个**，编号会接着往下排，不会重复

点 **处理记录** 按钮可以看到所有历史，选中某一次后可以：
- **这次处理了哪些文件夹**：每个原始文件夹 → 编号、状态、文件数、时间点（从映射表读取）
- **核对原始数据文件夹**：列出这个原始数据文件夹现在的每个子文件夹，标出 已完成 / 未完成 / 从未处理。以后往里面加了新患者，用这个就能看出哪些还没做
- **填入这组路径**、打开日志、打开映射表、打开输出文件夹

记录保存在本机（Windows：`%APPDATA%\CT_Deid\处理记录.jsonl`），只有时间、路径、数量和结果，**不含患者姓名、ID 和患者文件夹名**；每个患者的明细在映射表里。记录文件只追加、不修改。命令行查看：`python app.py --history`

映射表新增了两列："原始数据文件夹"和"批次"（对应处理记录里的某一次）。旧版映射表会自动补上这两列（补之前先备份）。没有 DICOM 的文件夹（比如只有图片）现在也会在映射表里记一行"跳过"，方便以后核对。

## 做了哪些处理

| 内容 | 处理 |
|---|---|
| 文件夹名、文件名 | 改为 `P0001/S01/0001.dcm` |
| 患者姓名、患者 ID | 换成编号（RadiAnt 里看到的就是 `P0001`） |
| 出生日期、所有日期 | 清空 |
| 年龄、性别、身高、体重 | **保留**（没有年龄字段时，用出生日期和检查日期算出检查时年龄） |
| 检查号、医院、科室、医生、技师、地址、电话、设备序列号、工作站名 | 删除或清空 |
| 所有 UID | 重新生成。同一患者内引用关系保持一致；同一映射表下重复处理，UID 也一致 |
| 厂商私有字段、Overlay、缩略图、尾部填充 | 删除 |
| 任何人名字段（含嵌套序列） | 清空 |
| 其他文本字段里出现的患者姓名/ID（拼音、中文、有无空格） | 清空该字段 |
| DICOMDIR、txt/pdf/jpg 等非 DICOM 文件 | 不复制，日志里列出 |
| 层厚、像素间距、位置、方向、窗宽窗位、重建核、设备型号、序列描述等 | **保留**，供分割/标注 |
| 像素数据 | 不动 |
| 截图、三维渲染图、剂量报告等序列（图上可能直接印着姓名） | **整个序列不输出**（见下） |

## 暂停、停止和续跑

- **暂停 / 继续**：处理过程中随时可以暂停。各进程会先写完手上的文件再停住，不会留下写了一半的文件
- **停止**：同样先写完当前文件再结束。以后用**同一个输出文件夹、同一个映射表**再点"开始脱敏"，会从停下的地方继续
- **处理中关闭窗口**：会先正常停止，等后台进程都结束后再自动关窗，不会出现界面关了后台还在写文件的情况
- 结构探查也可以暂停和停止（停止后不生成报告）

## 速度、空间不足和续跑

- **并行进程数**：界面上可以调。数据和输出都在固态硬盘上，可以调到 6–8；机械硬盘、U 盘或网络盘建议 2–4，开太多反而会因为磁盘来回寻道变慢。处理时状态栏会显示"每秒多少个文件"，结束时日志里也有平均速度，可以换几个进程数比一比
- **怎么做到快的**：
  - 脱敏只改文件头，像素不动。每个字段先按字段号和类型判断，只有 UID、自由文本、嵌套序列这类需要看内容的字段才解码；数值、像素、厂商私有大字段要么原样拷贝，要么直接删掉，不做任何转换（结果和逐个解码完全一致，有测试对比）
  - 每个文件一次读进内存、一次写出
  - 扫描和脱敏都把文件切成小块（每块几十个文件）分给所有进程，一个 1600 张的大患者也会被所有核心一起处理，不会最后只剩一个核心在跑
  - 扫描和脱敏共用同一组子进程，不重复启动
- **Windows 上进一步提速**（需要电脑管理员权限，按你们单位的规定来）：
  - **输出放到另一块硬盘**，最好是固态硬盘。原始数据和输出在同一个盘上时，确认窗口会提示
  - Windows 安全中心（Defender）会扫描每个新写出的文件，文件多时很耗时间。可以在"病毒和威胁防护 → 排除项"里把**输出文件夹**加进去（只加输出文件夹，不要加整个盘）
- **开始前检查空间**：确认弹窗里会显示"预计输出约 X GB，输出盘剩余 Y GB"。输出大小约等于原始 DICOM 的大小
- **空间写满时自动停止**：不会刷屏报错，日志里会说明在哪个患者、哪个文件停下
- **续跑**：腾出空间后，用**同一个输出文件夹、同一个映射表**再点一次开始。编号不变，已完成的文件直接跳过（不覆盖），上次没写完的 `.part` 临时文件会被补写完整
- 续跑前会核对：输出文件夹里同编号的数据必须属于同一个患者，否则拒绝写入，防止把不同的人混在一起

每个文件在**写出之前**，软件会把它完整编码好，再在内存里独立校验一遍；校验不通过的文件**不会写出**：
- 在文件头的字节里搜索原姓名（拼音，以及 UTF-8 和 GB18030 编码的中文）和 ID
- 确认没有私有字段，人名和日期都已清空

任何一项不通过，该文件就不写出，并在日志和映射表的"状态"列里标出。

### 图像里直接印着姓名的序列：整个排除

三维重建截图（"Processed Images"、Volume Rendering）、剂量报告、屏幕截图这类图像，姓名、医院、出生日期是**画在像素上**的，改文件头去不掉。分割/标注用的是张数最多的那个原始 CT，这些图没有用处，所以默认**整个序列不输出**：

- **一定排除**（强信号）：彩色图像（RGB 等，CT 原始断层永远是灰度的）、截图类（Secondary Capture）、`BurnedInAnnotation=YES`、ImageType 标着屏幕截图/三维渲染、Modality 为 SC/OT
- **排除，但保护主序列**（弱信号，只是序列描述里有 DOSE、REPORT、SCREEN、截图 等词）：如果它恰好是该时间点张数最多的序列，就**保留**并在日志里提示人工检查，避免误删主 CT
- 排除了哪些序列（时间点、原序列号、描述、原因、文件数）写在日志和映射表的"疑似烧录文字的序列"列；确认窗口里也会先列出来
- 剩下的序列连续编号（S01、S02……），不留空号
- 如果某个文件夹里**全都是**这类图像，状态为"完成（全部是截图类图像，已排除，无输出）"
- 不想排除时，取消界面上的勾选（命令行加 `--keep-burned-in`），这时只做提示
- **之前版本的输出文件夹**：里面可能还留着这些截图序列，而且序列编号会和新规则对不上。软件会检查每个已有序列目录，对不上的患者直接跳过并说明原因（不会混写，也不会删除）。**请换一个新的输出文件夹**，编号由映射表决定，不会变

这只能挡住设备有标记的、或者彩色的截图。灰度、又没有任何标记的截图仍然可能漏掉，发出前建议抽查几个患者。

## 结构探查（调整规则用）

点 **结构探查**，会生成一份报告。报告只统计数据的"形状"：层级、文件数、出现过哪些字段、厂商私有字段、哪些字段里出现过患者姓名，以及模拟脱敏后是否有残留。报告**不含**姓名、ID、日期、文件夹名、文件名。为了速度，每个文件只打开一次、只解析文件头最前面一小段（约几 KB，不碰私有大字段和像素）；每个序列只抽首/中/尾 3 个文件做全字段分析；所有文件按每批 100 个多进程并行，进度条和剩余时间实时显示。探查只是摸底，正式脱敏时仍会逐个文件处理和校验。自己看过确认后，可以发给开发者，用来针对你们医院的数据调整规则。

探查本身只读数据，唯一写盘的是最后保存报告。开始前会先检查报告要存的那个盘还有没有空间（少于 20 MB 直接提示换个位置，不白跑）；万一跑完保存时才遇到磁盘满（Errno 28），报告内容会显示在日志里，并弹窗让你换个位置另存，不用重跑。

## 开发（Mac / Windows 通用）

```bash
uv venv .venv -p 3.12 && uv pip install -p .venv/bin/python -r requirements.txt pytest numpy
.venv/bin/python tools/make_fake_data.py test_data/input     # 生成假患者测试数据
.venv/bin/python -m pytest -q tests                           # 自动测试
.venv/bin/python app.py                                       # 图形界面
.venv/bin/python app.py --input test_data/input --output test_data/output --mapping test_data/local/map.xlsx --yes
.venv/bin/python app.py --probe test_data/input --report probe.txt
```

## 打包 Windows exe

PyInstaller 不能在 Mac 上打 Windows 包，二选一：
- 在 Windows 上装 Python 3.12（安装时勾选 Add to PATH），把项目文件夹拷过去，双击 `build_windows.bat`，产物在 `dist\CT_Deid.exe`
  - 拷贝时**不要带 `.venv` 文件夹**（Mac 专用，Windows 上不能用）；`test_data`、`__pycache__` 也不需要
  - 不想打包也可以：双击 `run_from_source.bat` 直接运行（第一次会自动安装依赖）
  - 打包需要联网下载依赖。可以在任意一台联网的 Windows 电脑上打包，之后只把 `CT_Deid.exe` 一个文件拷到实际处理数据的电脑上，那台电脑不需要装 Python
- 把项目推到 GitHub，`.github/workflows/build-windows.yml` 会在云端的 Windows 环境里跑测试并打包，然后在 Actions 页面下载 exe

## 代码结构

- `deid/rules.py`：要删除或清空的字段表，调规则主要改这里
- `deid/anonymizer.py`：单个文件的脱敏逻辑
- `deid/pipeline.py`：扫描、编号、并行处理、校验
- `deid/mapping.py`：映射表（Excel；隐藏工作表 `_key` 存 UID 密钥，不要删）
- `deid/probe.py`：结构探查
- `deid/history.py`：处理记录（只追加）
- `deid/gui.py`、`deid/history_gui.py`：图形界面、处理记录窗口
- `tools/make_fake_data.py`：生成假数据
- `tests/`：自动测试
